# AGENTS.md

Working notes for AI coding agents in this repository. Human docs: `README.md` (features/build) and `DEVELOPMENT.md` (authoritative architecture reference — providers, cache policy, scoring, Android Auto; read the relevant section before touching those areas).

## Project

Android app (`com.autolyrics`) that fetches synced/karaoke lyrics for whatever is playing (MediaSession listeners like Spotify) and displays them in a phone UI and Android Auto. Kotlin, single `:app` module, no Compose — programmatic views installed by `AutoLyricsApp` activity callbacks.

## Build environment (hard constraints)

- JDK 21 installed → Gradle wrapper must stay >= 8.5 (currently 8.7).
- Release APKs are arm64-v8a only (`ndk.abiFilters` in `app/build.gradle.kts`; ML Kit `libtranslate_jni.so` is ~16 MB per ABI, so filtering cut 63 MB of native libs to 16). Debug builds keep all ABIs for emulators.
- Release builds run R8 with `proguard-android-optimize.txt` + no AGP default consumer rules; unit tests run unminified, so they cannot catch Gson/R8 reflection breakage (see DEVELOPMENT.md TypeToken incident) — smoke-test release network paths on-device.
- Android SDK at `$HOME/android-sdk`; `local.properties` (`sdk.dir=...`) is gitignored and must be recreated in fresh clones.
- Gates before declaring work done: `./gradlew assembleDebug testDebugUnitTest` (plain JUnit 4 tests under `app/src/test`, no Robolectric; keep new engine logic JVM-testable via `internal` pure functions).

## Architecture quick map

- `media/MediaListenerService` — session discovery/selection; the Media apps whitelist (`monitored_packages`, empty = all apps) filters candidates in `pickBestSession` via the pure `sessionAllowed` predicate before the PLAYING-preference race (phone + AA both honor it); `seen_media_packages` populates the picker; a prefs listener applies Save mid-playback.
- `media/MediaTracker` — singleton state owner: track changes, provider fetch, position, and translation trigger (`translateIfNeeded`), cancellation via per-purpose jobs. A race where every leg died transport-wise (timeout/429/5xx; 404s and Musixmatch 8xxxxxx are CLEAN misses) gets ONE backoff retry after 8 s (`isTransientMiss` + `AUTO_RETRY_BACKOFF_MS`) — clean empty answers never retry.
- `lyrics/` providers (`LrcLibClient`, `MusixmatchClient`, `PetitLyricsClient`, `SyncLrcClient`) ranked by `LyricsProviderResolver` (candidates whose payload is all non-lyric lines — blank/symbol/credit — are dropped before scoring — `hasDisplayableContent`, keyed on `LyricDisplay.isSymbolText`/`isCreditLine`; the same `hasDisplayableLines` gate filters Manual Search rows and re-checks lazy bodies at apply; `LyricDisplay.stripTitleArtistHeaders` — per-load at `MediaTracker.prepared`, the one site with track context, never persisted — drops LEADING title/artist header lines SyncLRC aggregates ship (`側面 - 張國榮`, `歌曲：X 歌手：Y`, title+artist pairs): first 3 lines only and only when FULL title AND artist both appear, so title-equal sung hooks survive); results cached by `LyricsCache` (STANDARD/KARAOKE variants of the SANITIZED line list — markers are derived at display time, never stored; permanent — a hit is final; Manual Search apply is the only refresh path and also force-retranslates). `ManualSearchDialog` (main-screen button) + `ManualSearch` implement the user-override search dialog across LRCLIB/SyncLRC/Musixmatch (+ PetitLyrics when configured) — parallel fault-isolated legs, each under its own 10 s timeout, per-leg diagnostics shown in the dialog status line; an Include-unsynced checkbox (default OFF) gates PLAIN rows, SyncLRC rows are exempt from the literal title filter (alias resolutions); overrides apply through `MediaTracker.applyManualLyrics`.
- `util/SungLine` — the single sung-line / marker-row source for ALL display surfaces (every AA browse builder, the browse refresh gate, and the AA now-playing card). Payloads are sanitized at ingest (`LyricDisplay.stripNonLyric` — blanks, music tags, section headers, and timed production credits (词：/曲：/Lyrics by …) never reach storage or display) and `virtualRows` interleaves the real lyric rows with DERIVED instrumental markers: intro when the first line starts >= 4 s in, interlude when the silence past a line's DERIVED end (last token start + 2 s word-timed, else start + 5 s line-timed) exceeds 5 s before the next start; the outro is a timing point (`outroStartMs`), never a row. Markers are first-class sequence rows — they preview, sing, page, and own board slots exactly like lyrics (board anchor trivially 0, intro-on-top emergent); `currentVIndex` picks the last row whose span has begun. Each marker row counts down to its OWN following line (`markerCountdownSeconds`), never the first-future line — a previewed marker holds the cap 4 while an earlier marker ticks. Card: identity until `CARD_LEAD_MS` (4 s) before the next line (mid-interlude too), then 4→1 countdown with the coming lyric; a sung line's subtitle preview never skips a row (`previewSuccessor` returns the next row whatever it is — with an instrumental next, the card previews the MARKER's glyph row like the tabs do; blank only past the last row); phone renders markers as static glyphs (digits are AA-only). The row-refresh gate tracks every field builders see (start/end/currentIdx/gap/countdown-signature/headerSec — the countdown field is a base-5 signature over ALL visible marker rows) or pushes get swallowed. Regression harness: `AaSequenceSimTest` sweeps playback through real provider payloads.
- Chinese targets are the two written forms (`zh-CN`/`zh-TW`, native-tail picker labels via `displayName`, plain `englishName` for prompts/status); already-Chinese lyrics in the other form convert OFFLINE per load at `MediaTracker.prepared` (`util/ChineseVariant`, OpenCC phrase+char dictionaries in assets, same-length UTF-16 pairs, kana hard-veto) — never engine-translated, never cached converted; legacy bare `zh` resolves to Simplified.
- Translation: two engines behind `lyrics/TranslationEngineUi` — `LyricsTranslator` (on-device ML Kit; language-pack download state machine) and `LlmTranslator` (OpenAI-compatible `/chat/completions`; JSON-array chunks, line-count validation, repair retries). Pref `translation_engine` routes; `TranslationCache` (filesDir/translation_cache, key = track+target+sha256(source text) — engine/model stored but not keyed; no expiry) is consulted first. Settings row `TranslationEngineView`, progress UI `TranslationStatusView` observes the active engine's `StateFlow`.
- `auto/LyricsBrowserService` — Android Auto browse tree (Lyrics · Karaoke · Sync · More; exactly 4 root tabs, the host caps at 4). Row text alignment and karaoke right-justification ride PIXEL-TUNED constants (`CURRENT_LINE_PREFIX`, `IDLE_LINE_PREFIX`, `TRANSLATION_SUBTITLE_PREFIX` in the service; `AaKaraokeRows` advance/column model; per-car column nudge persisted per head unit (`aa_karaoke_edge:<fingerprint>` int-delta prefs seeded from the global `aa_karaoke_edge`; identity = SHA-256 of the root-hints bundle in `auto/AaHost`; the RESOLVED column is PINNED per fingerprint in `aa_karaoke_column:<fp>` so column-model upgrades cannot move a calibrated edge — only the knob re-resolves it and Reset drops the pin; the settings Reset zeroes BOTH the live car and the global default — a per-car-only reset resurrects the old edge whenever the fingerprint drops; the header TITLE truncates at the column minus `HEADER_TITLE_INSET_EM` (2.0 em art inset — title field is larger-scale than the empirically-exact subtitle) minus `AaKaraokeRows.wordGuardEm` (widest Latin run, cap 2.5 em, zero for pure-CJK titles — Gearhead word-wraps, so a Latin-heavy title the model thinks fits still tips its last word onto line two; the guard lands the ellipsis before the wrap point) or the host wraps the spill and steals a board row), adjusted from the phone settings **Android Auto** section, which renders only while a head unit is connected and sits under the Phone section) — Gearhead strips/garbles leading whitespace in ways no font model predicts; retune only from head-unit (DHU) screenshots, see DEVELOPMENT.md "Host field rules". The Karaoke tab builds its board for FOUND **and** PLAIN_ONLY (position-estimated pair, `▶` kept, no countdown rows); only loading/not-found/error delegate to the Lyrics builder. The board is a CONSTANT two-line grid — with translations the lyric leads and the translation follows; without them the FIRST line is a `U+2800` blank and the lyric rides the SECOND — because Gearhead animates its list re-bind after every `notifyChildrenChanged` re-fetch and short variable-height rows make the per-second clock tick visibly jump (constant tall rows repaint silently). The settings Android Auto **Karaoke single lines** switch (`aa_karaoke_single_line`, OFF = grid) opts back into compact single-line rows in the no-translation state — reintroducing the tick-nudge by choice; translated rows are always two-line. Browse translations publish at run end (`visibleTranslations` hides the list while the engine runs — mid-run Lyrics/Sync stay single-line, no blank translation lines, no per-row height flips; the board is already constant-height so its publish flip is a text swap only); the refresh gate watches `translationsVisibleChanged` because engine completion emits no state change.
- Providers must never block playback: all network work runs off main; `Fetch` jobs are cancelled per-track.

## Conventions

- Objects/singletons for engines and clients; the main screen and settings panel are `activity_main.xml` rows wired in `MainActivity` (sections Media source / Phone / Android Auto / Lyrics, Media source first; the Android Auto section is connect-gated); dynamic rows (translation target/engine/status) are custom `LinearLayout`s installed from `AutoLyricsApp.onActivityResumed` with idempotent `install()`.
- SharedPreferences file name `auto_lyrics_prefs`; keys are `const val` on the owning class (`TranslationLanguages`, `LlmTranslator`, etc.).
- Failure UX: transient failures latch a manual-retry gate (see `prepareManualRetry`); never auto-retry in a loop, never log API keys.
- Remote LLM endpoints have no TLS requirement (server never runs on the phone; `usesCleartextTraffic` is enabled). Bare host input is normalized to `https://host/v1` by `LlmTranslator.normalizeBaseUrl`; the API key is optional. Model lists come from the endpoint's `/models` route with a manual-entry fallback. User-facing option lists stay intentionally small (see `TranslationLanguages.primaryTargets`).
