# AGENTS.md

Working notes for AI coding agents in this repository. Human docs: `README.md` (features/build) and `DEVELOPMENT.md` (authoritative architecture reference — providers, cache policy, scoring, Android Auto; read the relevant section before touching those areas).

## Project

Android app (`com.autolyrics`) that fetches synced/karaoke lyrics for whatever is playing (MediaSession listeners like Spotify) and displays them in a phone UI and Android Auto. Kotlin, single `:app` module, no Compose — programmatic views installed by `AutoLyricsApp` activity callbacks.

## Build environment (hard constraints)

- JDK 21 installed → Gradle wrapper must stay >= 8.5 (currently 8.7).
- Release APKs are arm64-v8a only (`ndk.abiFilters` in `app/build.gradle.kts`; ML Kit `libtranslate_jni.so` is ~16 MB per ABI, so filtering cut 63 MB of native libs to 16). Debug builds keep all ABIs for emulators.
- Release builds run R8 with `proguard-android-optimize.txt` + no AGP default consumer rules; unit tests run unminified, so they cannot catch Gson/R8 reflection breakage (see DEVELOPMENT.md TypeToken incident) — smoke-test release network paths on-device.
- Android SDK at `$HOME/android-sdk`; `local.properties` (`sdk.dir=...`) is gitignored and must be recreated in fresh clones.
- Gates before declaring work done: `./gradlew assembleDebug testDebugUnitTest` (plain JUnit 4 tests under `app/src/test`, no Robolectric; keep new engine logic JVM-testable via `internal` pure functions).

## Architecture quick map

- `media/MediaListenerService` — session discovery/selection; the Media apps whitelist (`monitored_packages`, empty = all apps) filters candidates in `pickBestSession` via the pure `sessionAllowed` predicate before the PLAYING-preference race (phone + AA both honor it); `seen_media_packages` populates the picker; a prefs listener applies Save mid-playback.
- `media/MediaTracker` — singleton state owner: track changes, provider fetch, position, and translation trigger (`translateIfNeeded`), cancellation via per-purpose jobs. Sync offsets: PER-LYRICS `lyrics_offset:<sha16(text+stamps)>` (the global `lyrics_offset_ms` is retired and dropped at init) swapped by a flow collector keyed on the published line list — writes no-op while nothing is loaded, zeros are removed; `getCurrentPositionMs()` includes it, so every surface rides it; the global `aa_offset_ms` (phone **Global AA Sync** row only, never shown on the car) stacks on top in the browse service. A race with no candidate and >=1 transport-dead leg (timeout/429/5xx; 404s and Musixmatch 8xxxxxx are CLEAN misses) gets up to TWO backoff retries after 3 s each (`isTransientMiss` + `AUTO_RETRY_BACKOFF_MS` + `AUTO_RETRY_MAX`), and each retry races ONLY the dead legs (`retryProviders`) — clean empty answers are final and never re-fetched. The resulting NOT_FOUND latch is PER PLAYBACK: only playback STARTING AT 0 again re-arms the full cycle (`replayRearmIfLatched`: PLAYING position inside 2 s after >=15 s heard) - seeks never trigger it, FOUND never re-fetches, and a running cycle (LOADING) is never doubled; pause/unpause never reloads.
- `lyrics/` providers (`LrcLibClient`, `MusixmatchClient`, `PetitLyricsClient`, `SyncLrcClient`) ranked by `LyricsProviderResolver` (candidates whose payload is all non-lyric lines — blank/symbol/credit — are dropped before scoring — `hasDisplayableContent`, keyed on `LyricDisplay.isSymbolText`/`isCreditLine`; the same `hasDisplayableLines` gate filters Manual Search rows, and lazy-provider (Musixmatch/PetitLyrics) bodies resolve eagerly at search time — `eagerBodies` fetches the top 6 per leg in parallel and drops unusable ones, so every listed row is clickable; `LyricDisplay.stripTitleArtistHeaders` — per-load at `MediaTracker.prepared`, the one site with track context, never persisted — drops LEADING title/artist header lines SyncLRC aggregates ship (`側面 - 張國榮`, `歌曲：X 歌手：Y`, title+artist pairs): first 3 lines only and only when FULL title AND artist both appear, so title-equal sung hooks survive; both sides' match keys fold the two Chinese WRITTEN FORMS via the offline OpenCC simp-table (live case: session tag 涼茶王 against a 凉茶王-东山少爷 header line — mixed-script file tags are common for Cantonese songs), so a trad/simp mismatch never resurrects a header); results cached by `LyricsCache` (STANDARD/KARAOKE variants of the SANITIZED line list — markers are derived at display time, never stored; permanent — a hit is final; Manual Search apply is the only refresh path and also force-retranslates). `ManualSearchDialog` (main-screen button) + `ManualSearch` implement the user-override search dialog across LRCLIB/SyncLRC/Musixmatch (+ PetitLyrics when configured) — parallel fault-isolated legs, each under its own 10 s timeout; the title field is MANDATORY (Search refuses blank titles; artist optional); the dialog status line shows ONLY the outcome (`N results · track m:ss` / `0 results…` / red `Error…` when nothing listed and ≥1 leg died transport-wise — per-leg transport deaths flow through `launchManualSearch`'s `deaths` list), and tapping it opens the full per-provider diagnostics; an Include-unsynced checkbox (default OFF) gates PLAIN rows, SyncLRC rows are exempt from the literal title filter (alias resolutions); overrides apply through `MediaTracker.applyManualLyrics`. SyncLRC never skips on blank artist, but `/lyrics` REQUIRES both params (title-only is a contract 400) so blank artist drops the exact stage in both paths: auto goes ladder-only (guess mode on duration+title), manual lists the catalog ladder over the whole iTunes page (`CATALOG_LOOKUP_LIMIT_MANUAL = 6`, deduped against the exact row when an artist was given so it is never re-fetched); leg diagnostics use the uniform body-leg vocabulary `synclrc: N` (all fetches usable) / `synclrc: k/n usable` (candidates dropped — ladder deaths fold into the fraction Musixmatch-style, they are NOT death lines) / `synclrc: 0 (no catalog match)` / `synclrc: <cause>` (request-level death with nothing probed).
- `util/SungLine` — the single sung-line / marker-row source for ALL display surfaces (every AA browse builder, the browse refresh gate, and the AA now-playing card). Payloads are sanitized at ingest (`LyricDisplay.stripNonLyric` — blanks, music tags, section headers, and timed production credits (词：/曲：/Lyrics by …) never reach storage or display) and `virtualRows` interleaves the real lyric rows with DERIVED instrumental markers: intro when the first line starts >= 4 s in, interlude when the silence past a line's DERIVED end (last token start + 5 s word-timed, else a syllable-proportional hold: `PronouncedLength.estimate(text)` x `MS_PER_SYLLABLE` 800 ms clamped 2-15 s - the estimator counts morae per script, kanji priced by the JMdict-derived `assets/japanese/kanji_mora.txt` table in kana lines, 1/char otherwise) exceeds 5 s before the next start; the outro is a timing point (`outroStartMs`), never a row. Markers are first-class sequence rows — they preview, sing, page, and own board slots exactly like lyrics (board anchor trivially 0, intro-on-top emergent); `currentVIndex` picks the last row whose span has begun. Each marker row counts down to its OWN following line (`markerCountdownSeconds`), never the first-future line — a previewed marker holds the cap 4 while an earlier marker ticks. Card: identity until `CARD_LEAD_MS` (4 s) before the next line (mid-interlude too), then 4→1 countdown with the coming lyric; a sung line's subtitle preview never skips a row (`previewSuccessor` returns the next row whatever it is — with an instrumental next, the card previews the MARKER's glyph row like the tabs do; blank only past the last row); phone renders markers as static glyphs (digits are AA-only). The row-refresh gate tracks every field builders see (start/end/currentIdx/gap/countdown-signature/headerSec — the countdown field is a base-5 signature over ALL visible marker rows) or pushes get swallowed. Regression harness: `AaSequenceSimTest` sweeps playback through real provider payloads.
- Chinese targets are the two written forms (`zh-CN`/`zh-TW`, native-tail picker labels via `displayName`, plain `englishName` for prompts/status); already-Chinese lyrics in the other form convert OFFLINE per load at `MediaTracker.prepared` (`util/ChineseVariant`, OpenCC phrase+char dictionaries in assets, same-length UTF-16 pairs, kana hard-veto) — never engine-translated, never cached converted; legacy bare `zh` resolves to Simplified.
- Translation: two engines behind `lyrics/TranslationEngineUi` — `LyricsTranslator` (on-device ML Kit; language-pack download state machine) and `LlmTranslator` (OpenAI-compatible `/chat/completions`; JSON-array chunks, line-count validation, repair retries). Pref `translation_engine` routes; `TranslationCache` (filesDir/translation_cache, key = track+target+sha256(source text) — engine/model stored but not keyed; no expiry) is consulted first. Settings row `TranslationEngineView`, progress UI `TranslationStatusView` observes the active engine's `StateFlow`.
- `auto/LyricsBrowserService` — Android Auto browse tree (Lyrics · Karaoke · Sync · More; exactly 4 root tabs, the host caps at 4). Row text alignment and karaoke right-justification ride PIXEL-TUNED constants (`CURRENT_LINE_PREFIX`, `IDLE_LINE_PREFIX`, `TRANSLATION_SUBTITLE_PREFIX` in the service; `AaKaraokeRows` advance/column model; per-car column nudge persisted per head unit (`aa_karaoke_edge:<fingerprint>` int-delta prefs seeded from the global `aa_karaoke_edge`; identity = SHA-256 of the root-hints bundle in `auto/AaHost`; the RESOLVED column is PINNED per fingerprint in `aa_karaoke_column:<fp>` so column-model upgrades cannot move a calibrated edge — only the knob re-resolves it and Reset drops the pin; the settings Reset zeroes BOTH the live car and the global default — a per-car-only reset resurrects the old edge whenever the fingerprint drops; the header TITLE truncates at the column minus `HEADER_TITLE_INSET_EM` (2.0 em art inset — title field is larger-scale than the empirically-exact subtitle) minus `AaKaraokeRows.wordGuardEm` (widest Latin run, cap 2.5 em, zero for pure-CJK titles — Gearhead word-wraps, so a Latin-heavy title the model thinks fits still tips its last word onto line two; the guard lands the ellipsis before the wrap point) or the host wraps the spill and steals a board row), adjusted from the phone settings **Android Auto** section, which renders only while a head unit is connected and sits under the Phone section) — Gearhead strips/garbles leading whitespace in ways no font model predicts; retune only from head-unit (DHU) screenshots, see DEVELOPMENT.md "Host field rules". The Karaoke tab builds its board for FOUND only; loading/not-found/error delegate to the Lyrics builder. PLAIN_ONLY (unsynced payload — auto race or cached) is the HONEST STATIC state everywhere: the Lyrics tab lists EVERY line at once (touch-scrollable, no window slide, no `▶`, `plain_line_N` ids so taps never seek the zero stamps) under a header whose tail shows the track DURATION (never a ticking clock — the gate reports a constant plain signature, so nothing re-pushes and the scroll never resets under a finger); Karaoke and Sync show the `No synced lyrics found` message row (Sync without its offset/± rows); the now-playing card rides the NOT_FOUND identity layout with that subtitle for 15 s; the phone renders a static sheet (the old position/duration crawl is deleted — it faked sync). Without translations the board is COMPACT SINGLE LINES (the constant two-line grid + its `aa_karaoke_single_line` settings switch were retired by user decision; removing the over-column `padEnd(60)` padding killed the worst jump class but the flip SURVIVES on byte-identical rows - tall-row camouflage was demoted, not defeated, see THE OPEN FLIP below; the pref is deleted and unread). With translations the lyric leads and the translation follows (missing translation = `U+2800` filled second line, constant height through the run); an empty hold slot rides a `U+2800` row so it never collapses. Browse translations publish at run end (`visibleTranslations` hides the list while the engine runs — mid-run Lyrics/Sync stay single-line, no blank translation lines, no per-row height flips; the board's publish flip is a one-time height change per run, accepted); the refresh gate watches `translationsVisibleChanged` because engine completion emits no state change; every row string entering a browse list is column-fit by `rowFit` (over-column fields get word-wrapped by the host). The short-row flip under the 1 Hz clock rebind is a KNOWN OPEN Gearhead behavior (immune: tabs without the header tick, or constant-height rows) - see DEVELOPMENT.md "THE OPEN FLIP" before proposing another content-side fix.
- Providers must never block playback: all network work runs off main; `Fetch` jobs are cancelled per-track.

## Conventions

- Objects/singletons for engines and clients; the main screen and settings panel are `activity_main.xml` rows wired in `MainActivity` (sections Media source / Phone / Android Auto / Lyrics, Media source first; the Android Auto section is connect-gated); dynamic rows (translation target/engine/status) are custom `LinearLayout`s installed from `AutoLyricsApp.onActivityResumed` with idempotent `install()`.
- SharedPreferences file name `auto_lyrics_prefs`; keys are `const val` on the owning class (`TranslationLanguages`, `LlmTranslator`, etc.).
- Failure UX: transient failures latch a manual-retry gate (see `prepareManualRetry`); never auto-retry in a loop, never log API keys.
- Remote LLM endpoints have no TLS requirement (server never runs on the phone; `usesCleartextTraffic` is enabled). Bare host input is normalized to `https://host/v1` by `LlmTranslator.normalizeBaseUrl`; the API key is optional. Model lists come from the endpoint's `/models` route with a manual-entry fallback. User-facing option lists stay intentionally small (see `TranslationLanguages.primaryTargets`).
